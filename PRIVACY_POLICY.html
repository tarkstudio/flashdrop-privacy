02

Architecture Overview: Offline-First, Zero-Server Design

FlashDrop operates on a purely offline peer-to-peer (P2P) architecture. This is a foundational design principle, not merely a configuration choice.

✓ No remote servers  ·  ✓ No data uploads  ·  ✓ No accounts required  ·  ✓ Local socket only

How a Transfer Works

  1. Your device opens a local socket (e.g., 192.168.x.x) and advertises availability within the local network only.
  2. A receiving device discovers this socket via mDNS/Bonjour broadcast, QR code scan, or manual IP entry — all local operations.
  3. The file is streamed directly from the sending device's local storage to the receiving device's local storage.
  4. The Developer's systems are never involved at any stage.
03

Permissions Used and Their Justification

The Application requests certain Android system permissions. Each permission is used solely for the technical operation of local file transfers. The Developer makes the following binding representations:

Permission Purpose Remote Telemetry?
READ_EXTERNAL_STORAGE / READ_MEDIA_* Read files selected by the user for outbound transfer ❌ Never
WRITE_EXTERNAL_STORAGE Write incoming files to the device's storage ❌ Never
ACCESS_WIFI_STATE / CHANGE_WIFI_STATE Detect active network interfaces for socket binding ❌ Never
ACCESS_NETWORK_STATE Check local network connectivity before initiating streams ❌ Never
CHANGE_NETWORK_STATE Configure local hotspot or Wi-Fi Direct connections ❌ Never
NEARBY_WIFI_DEVICES Discover peer devices for Wi-Fi Direct pairing (Android 12+) ❌ Never
ACCESS_FINE_LOCATION Required by Android OS for Wi-Fi scanning APIs — no location data is stored or transmitted ❌ Never
FOREGROUND_SERVICE Keep transfer socket alive during background/screen-off scenarios ❌ Never
CAMERA (optional) Scan QR codes for peer discovery; no images are stored ❌ Never
POST_NOTIFICATIONS Display transfer progress notifications ❌ Never

Location Permission Clarification

Android's Wi-Fi scanning API mandates ACCESS_FINE_LOCATION at the OS level. FlashDrop does not read, record, process, or transmit your geographic location. This is an OS-enforced prerequisite for Wi-Fi Direct peer discovery only.

05

Local Data Storage

The Application may store the following data locally on your device only:

  • Received files: Saved to your chosen destination folder. The Developer has no access to these files.
  • App preferences: Settings such as preferred transfer mode or last-used save path, stored in Android SharedPreferences. Never transmitted externally.
  • Temporary socket state: In-memory session data (pairing codes, socket handles) that is discarded when the transfer session ends or the Application is closed.

✓ All locally stored data remains under your exclusive control and can be deleted at any time via the Application's settings or by uninstalling the Application.

06

Network Security and Open Wi-Fi Disclosure

6.1 Encryption Status

In its current version, FlashDrop performs transfers over plain TCP/UDP sockets without end-to-end application-layer encryption. Transfers rely on the security of the local network environment.

⚠ Open Network Warning

Transfers over open, unencrypted, or public Wi-Fi networks are undertaken entirely at the User's own risk. The Developer is not responsible for any interception, eavesdropping, or data capture by third parties on the same network. Use a private, password-protected, or personal hotspot for sensitive transfers.

6.2 User Responsibility for Network Security

  • The Developer is not liable for any privacy breach, data exposure, or unauthorized access arising from the User's choice to operate the Application on an open or untrusted network.
  • Users are strongly advised to perform transfers exclusively over private, password-protected, and trusted Wi-Fi networks or via a device-controlled personal hotspot.
  • Other devices on the same open network segment may theoretically intercept raw socket data using packet capture tools.
